# PCP Streaming RPA Kernel

This directory contains the prefill context parallel (PCP) implementation for
TPU ragged paged attention. The kernel computes full causal prefill attention
without gathering the whole KV cache onto every rank. Instead, each PCP rank
keeps a local shard of the paged KV cache and streams KV pages around a PCP ring
while computing attention for its local query tokens.

## High-Level Flow

The production vLLM path enters through `vllm_adapter.py` and `wrapper.py`.
The attention backend passes the standard vLLM metadata tensors:

- `seq_lens`: total KV length for each active request.
- `block_tables`: paged KV cache block table for each request.
- `query_start_loc`: cumulative query-token offsets for the current batch.
- `request_distribution`: vLLM request distribution metadata.

`wrapper.py` runs inside a JAX `shard_map` over the PCP mesh. Inside each PCP
rank it first writes that rank's new K/V rows into the local paged KV cache
shard, then calls the Pallas kernel in `kernel.py`.

The Pallas kernel consumes a packed schedule generated by `schedule.py`. A
schedule step tells one consumer rank which remote or local KV page to consume,
where the current query tile lives in HBM, and whether the step begins or ends
an online-softmax accumulation for that tile.

## Token and Cache Layout

PCP uses rank-major token packing. For a configured `pcp_size` and
`cp_kv_cache_interleave_size`, global query positions are split into interleave
chunks:

```text
rank 0: [0, interleave), [pcp_size * interleave, ...]
rank 1: [interleave, 2 * interleave), ...
...
```

The host runner packs these chunks by rank before moving inputs to the device.
Each rank therefore sees compact local query rows, but the kernel reconstructs
the original global query position from the schedule when applying the causal
mask.

The KV cache is striped by page across PCP ranks. Global page `p` is stored on
rank `p % pcp_size`, at local page `p // pcp_size`. During attention, each page
group streams one page from each rank around the ring so every consumer rank can
attend to all pages needed by its query tile.

## Schedule Shape

The packed schedule has shape:

```text
[steps, pcp_size, num_lanes, 128]
```

The first `ScheduleField.NUM_FIELDS` entries are logical fields, and the rest
are padding/reserved space. The production metadata path currently uses one
lane and one KV page per source-rank step. Steps are padded so each page group
contains exactly `pcp_size` steps.

Important fields include:

- `REQ_ID`: active request id, or `-1` for padded/inactive steps.
- `KV_PAGE_RANK`: source PCP rank for the scheduled KV page.
- `KV_PAGE_IDX`: local KV cache page index on that source rank.
- `IS_FIRST_KV`: reset online-softmax state and load the Q tile.
- `IS_LAST_KV`: store the final output for the Q tile.
- `Q_GLOBAL_START`: global position of the first row in the local compact Q
  tile.
- `KV_GLOBAL_START`: global position of the first KV token in the scheduled
  page.
- `KV_VALID_LEN`: number of valid KV tokens in the scheduled page.
- `Q_HBM_OFFSET` and `O_HBM_OFFSET`: local compact query/output offsets.
- `Q_TILE_SIZE`: number of valid rows in the local Q tile.

## Kernel Execution

For each lane and page group, the kernel:

1. Loads the schedule row for the current rank and loads the local Q tile if
   `LOAD_Q` is set.
2. Loads the local KV page for this rank into one of two VMEM slots.
3. Runs `pcp_size` ring rounds. In each round it consumes the current VMEM KV
   slot, asynchronously sends it to the next rank, waits for the previous
   transfer as needed, and swaps slots.
4. Updates online-softmax state `(m, l, acc)` for every consumed page.
5. Stores `acc / l` back to HBM when the group contains the last KV page for
   that Q tile.

The single-head and multi-head kernels share the same ring structure. The
multi-head path consumes a packed batched-RPA KV-cache layout and reuses the
same ring transfer for all local KV heads.

## Entry Points

- `pcp_streaming_attention_page_groups_packed_local_from_metadata`: production
  metadata-driven entry. It builds a JAX schedule from vLLM metadata, then runs
  the packed-local kernel.
- `pcp_streaming_attention_page_groups_packed_local`: runs an already-built
  schedule against a local packed KV-cache shard.
- `pcp_streaming_attention_page_groups_local`: test/debug entry for the
  unpacked KV-cache layout.
- `pcp_streaming_attention_page_groups`: test/debug entry for tensors that
  still have an explicit leading PCP-rank dimension.

## Current Constraints

The production path is intentionally narrow:

- Full attention only; sliding-window attention is not supported here.
- `cp_kv_cache_interleave_size == page_size`.
- `q_block_size` must be a multiple of the interleave size.
- The metadata schedule path supports `num_lanes == 1` and
  `kv_pages_per_block == 1`.
- `head_dim == 64` and attention sinks are not supported.
- The kernel expects to update the KV cache before computing attention.
